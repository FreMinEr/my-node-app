# Лабораторная работа №24

Парфёнок Иван, группа 477. Выполнены задания 1-3.

```powershell
cd lab24
npm ci
Copy-Item .env.example .env
# Указать свой MongoDB URI и пароль
npm start
# В другом терминале, при доступной MongoDB:
npm test
```

`task1.js`, `task2.js`, `task3.js` запускают соответствующие этапы на порту
3000 (или PORT). Общая реализация находится в app.js. MongoClient создается
один раз при старте; подключения и HTTP-сервер закрываются по Ctrl+C.

1. CRUD `/api/users` и `/api/users/:id`, уникальный индекс email, валидация,
   JSON с data/error, коды 400/404/409/500, заголовок X-Group: 477.
2. Модель User со статическими методами, сервис, контроллер, маршруты,
   middleware db/error/logger/validation. Joi проверяет вход и модель повторно
   проверяет данные. Необязательный пароль хэшируется scrypt и никогда не
   возвращается. Email-уведомления только имитируются в журнале.
3. Пагинация page/limit (максимум 100), фильтры group_name/course/age_min/age_max,
   sort из белого списка, текстовый search с релевантностью; `/search?q=...`,
   `/stats` (агрегация), `/export` (потоковый CSV с экранированием).

Пример тела POST:

```json
{"name":"Парфёнок Иван","email":"ivan@example.com","group_name":"477","age":20,"course":2}
```

PUT принимает частичное изменение. Формат группы из методички ББМО-XX-XX
поддержан, дополнительно разрешена реальная группа автора 477.
Возраст и курс необязательны, при передаче должны быть целыми в диапазонах
16-100 и 1-4. Неизвестные поля и параметры отклоняются. Невалидный ID дает 404.
Текстовый поиск — поиск слов MongoDB, не поиск произвольной подстроки.

`npm test` требует реальную MongoDB, создает только собственные записи с
уникальным префиксом email и очищает их после теста. Проверяет CRUD, Joi,
дубликаты, пагинацию/фильтры/сортировку, поиск, статистику и CSV.
Задания 4-5 (JWT и прочее) не включены.
